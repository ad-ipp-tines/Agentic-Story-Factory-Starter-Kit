# POLICY.md — the governance contract

_Read this first if you are the security reviewer. Every statement here is enforced by a file you can diff: a permission rule, a hook, a workflow, a Tines setting or a Resource. Where enforcement depends on unverified product behaviour, the line says **VERIFY**._

## 2. Rules

1. **Change control on every story.** Tenant policies **Enable by default** and **Require approval for all changes** are on, admins and owners included; story requirements (name, description, owners, tags, event retention) are set to required.
2. **Production is reached only by import → named draft → change request → a named person approving in Tines.** `ship.yml` opens the request and stops. `promote.yml` promotes only a request whose status is APPROVED, with `delete_draft: true` and never `bypass_approval`.
3. **No bypass outside the `break-glass-promote` job.** `cr-promote` is denied in the IDE (`.claude/settings.json`); the dispatcher accepts `--bypass-approval` only when `BREAK_GLASS=1` and `--reason` are set. Only `rollback.yml`'s three break-glass jobs set `BREAK_GLASS=1` — `break-glass` (disable), `break-glass-promote` (promote the rollback; `bypass_approval` only if the request is still not APPROVED) and `break-glass-re-enable` — and `promote_change_request.py` accepts a bypass only inside `break-glass-promote`.
4. **Every promoted change carries the commit SHA** in the change-request description (`scripts/tines cr-open` template: story · environment · commit SHA · PR URL · semantic diff · rollback ref) **and a story version** (`POST /api/v1/stories/{id}/versions`, named `pre-ship <sha>` before and `release <sha>` after).
5. **Nightly drift check.** `drift.yml` exports every production story, diffs it against `main`, attributes any deviation through the audit logs (`user_email`, `operation_name`, `source`, `request_user_agent`; MCP activity rows flagged) and opens a drift PR. The repository is the truth; the tenant is a deployment target.
6. **Audit logs leave the tenant through the native S3 export every 15 minutes** and are drained to the SIEM — not through a story. Default retention is two years.
7. **MCP activity is part of every review.** The Tines Stories MCP server logs each tool use as MCP activity; `guard-mcp.sh` mirrors every call locally to `.tines/mcp-activity.jsonl`; the reviewer reads the rows for the story since the session started.
8. **The generator never reviews its own work.** `/tines-review` runs in a fresh context (`tines-reviewer`: no MCP, read-only tools) and refuses if the session built the story; `review.yml` is a separate Claude Code instance with no MCP and no tenant credentials; CODEOWNERS adds a person; branch protection forbids self-merge.
9. **Budgets are files.** `policies/cost-ceilings.yml` is the single source; every new AI Agent action needs a line there (`lint.yml` fails the PR otherwise); every agent carries a token-usage alert on its Status tab (Notify, then Disable action); the sweep spends credits only on anomalies.
10. **No secrets in the repository.** Exports carry no credentials, resources or events by design; `clear_recipients=true` on export; `block-secrets.sh`, `lint-story.sh`, `lint.yml` and gitleaks are the backstop, not the rule. The router webhook URL carries a secret and lives only in `.env` / GitHub environment secrets. Credentials in Tines carry `allowed_hosts`, `expires_at` with expiry notifications, and Workbench access **off** for pipeline keys.
11. **Keys are team-scoped, role-bound, rotated quarterly, never personal.** Created only by holders of the key-creation permission; stored as GitHub **environment** secrets; an underprivileged key gets a 404 and the dispatcher names it as such.
12. **Guards live in the story, not in prompts.** Kill switch (`ops_limits.enabled`), compare-and-swap lock (`ops_lock`), responder allow-list (`ops_responders`), never-touch mirror, request tools instead of write tools, approvals to a fixed channel with an expiry, escalation on explicit schema fields only.
13. **Never-touch is machine-read.** `policies/never-touch.yml` lists production story ids, `[OPS]` name patterns, the `90 Seeds` folder and the prod team. Its consumers: `guard-mcp.sh` (`story_ids`, `teams`, `folders` and `name_patterns`, plus the manifest's prod story ids, prod `team_id` and prod `folder_id`; ids matched as numbers or digits-only strings, patterns against every string in the tool input; fails closed when `jq`, `yq` or either file is missing), `set_monitoring.py` and `story_disable.py` (`story_ids`; writes only inside a ship's or rollback's own draft, disables only under break-glass), `propose-fix.yml` (`story_ids` and `name_patterns`), and the monitor's Conditions through the `never_touch` mirror in the `ops_limits` Resource. `lint-story.sh` does not enforce it (`never_touch_targets` is not implemented in `lint_story.py`); only `guard-mcp.sh` reads the `folders` and `teams` entries.
14. **Headless runs are fenced.** `propose-fix.yml` runs a pinned (exact-version) Claude Code CLI with `--setting-sources project` (this repository's skill and its hooks load — trusted because `repository_dispatch` runs on the default branch and a `workflow_dispatch` from any ref other than `main` is refused), no `jq`/`yq`/`env` in the model's tools, a commit rebuilt deterministically and secret-scanned before any push, `--strict-mcp-config` with an empty `--mcp-config` (no MCP server), explicit `--allowedTools` and `--disallowedTools` lists, `--max-turns`, a timeout, and a checkout with no persisted git token (the model's step holds no GitHub token and no Tines key). `review.yml` runs `claude-code-action` with `--setting-sources project` over the **base branch's** `.claude/` (skills, the reviewer agent, permission rules, hooks, the findings schema) and the base branch's `scripts/` — the pull request's checkout is data only, so a PR cannot rewrite its own reviewer, hooks or scripts — with no `id-token: write`, a read-only `--allowedTools` list, `--max-turns` and a timeout, on same-repository PRs only; it configures no MCP server (whether the action adds servers of its own is VERIFY #21) and holds no Tines credential. Fork PRs receive no secrets; `allowed_bots` is empty.
15. **Data policy is named.** Mode 2 runs on the editor's provider, so the organisation's editor data policy — not Tines' foundation guarantees — governs what the model sees; story exports contain configuration only. Modes 1 and 3 run on Tines-provided or custom providers under the tenant's AI settings.
16. **Agents never merge, approve a gate or promote.** The lifecycle's crew author branches, pull requests, Records rows and proposals, and nothing else: every new IDE crew member has `disallowedTools: Write, Edit`; Write and Edit are denied on `.storyline/**`, `kit/tracker/**` and `storyline/work/**` (`.claude/settings.json`); `/storyline-gate` is human-only (`disable-model-invocation: true`); and `./scripts/storyline gate` asks for a confirmation on `/dev/tty`, which a model's Bash call cannot supply. Authority for a gate comes from versioned files (`storyline/gates/approvers.yaml`, CODEOWNERS, the `storyline_approvers` Resource), never from a chat reply.
17. **Tines-side crew hold no tools and no credentials.** `planner`, `brief_writer` and `retro_writer` in `[KIT] 00` section D are tool-less AI Agent actions with an output schema, a Trigger on schema fields after each, a token alert, a budget line and a pinned fast model. Their inputs are data and their outputs are proposals a person accepts. None runs until a person sets `storyline_limits.guards_confirmed` and `storyline_limits.enabled` after the token alerts and skills are in place.
18. **Every lifecycle state change reaches `main` only through a pull request a person merges.** `./scripts/storyline` and `./scripts/kit tracker-fold` are the only writers of `kit/tracker/**` and `storyline/work/**`. A decision made in Tines stays provisional (`pending_repo_sync`) until its tracker PR merges. `storyline.yml`, the one required check, enforces the touch set by branch prefix, `rev` = `main`'s rev + 1, append-only `events.jsonl`, and an approving review from the gate's team for every added `gate_decision` event.

## 3. What never happens

- A pipeline approves a change request.
- A pipeline promotes a PENDING change request or passes `bypass_approval` outside `rollback.yml`'s `break-glass-promote` job.
- A `/mcp` call runs against production (`TINES_ENV=prod`) or references a never-touch story id.
- An AI Agent action holds a write credential, or a tool named `block|delete|isolate|disable` exists without a `request_` prefix.
- A credential value, resource content, token or webhook secret is written to the repository, a prompt or an MCP connection.
- A story ships with `tier: production` and no `monitor_failures`, no recipients, or an AI Agent action without an output schema, a post-agent Trigger, a token alert and a budget line.
- Anyone hand-edits `story.json`.
