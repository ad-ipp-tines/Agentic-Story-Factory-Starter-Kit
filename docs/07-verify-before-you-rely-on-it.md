# 07 · Verify before you rely on it — the consolidated VERIFY list, with how to check each in your tenant

_Tines Stories as Code · docs v1 (2026-09-24) · Matches `DESIGN.md` §10 (items 1–28) plus three items surfaced by the research (E1–E3) · Nothing here is a headline claim. The **ledger** of what your tenant has confirmed is `VERIFY.md`; this file is the method._

## How to use this list

- **"Assumed"** is what the repository designs around. It is not a fact until your tenant says so.
- **"How to confirm"** names the page, the API call or the client to look at — a builder can do it in an afternoon on a scratch team.
- **"What changes when confirmed"** is the edit you make to the repo, so a confirmation is never just a checkbox.
- **"Blocks"** says which claim or file cannot be presented as fact until then.
- **Owner** is a role: *builder* (anyone with the editor), *ops* (the team that owns the ops trio), *platform* (a tenant owner or admin), *account* (the Tines account team).
- Both sides of any **CONFLICT** are kept until resolved.

Record each confirmation in `VERIFY.md` (date, role, what you saw, what changed). Never present an item as fact from this file alone.

## The first afternoon — check these in this order

1. **Item 3** (connect) → **Item 1** (tool names) → **Item 5** (subagent server reference) — one `/tines-connect` and one `/tines-build-story` on a scratch story settle all three.
2. **Item 2** (`/mcp` × change control) — while you are in that scratch story.
3. **Item 8** (export key names) — one real export; this unlocks the exact lint rules.
4. **Item 13** (plan entitlements and flow counting) — one message to the account team; this decides whether the ops pair can exist.
5. **Item 9** (monitoring payload) — one deliberate failure in a LIVE scratch story with a test recipient; this tunes the router.

## What is **not** on this list (documented, no verification needed)

These are published Tines facts and can be stated: the Tines Stories MCP server is OAuth only and an API key will not work · each `/mcp` tool use is recorded in audit logs as MCP activity · the server exposes Workbench story-building capabilities (reading and changing stories, creating and updating actions, validation, running actions where permitted, research and listing helpers, private template operations when your permissions allow) and cannot see credential values or resource contents — through it an editor can list and read the stories the user has access to, one story at a time (the "cannot see other stories" limit is documented for the Workbench for Storyboard engine's own scope, not for this server) · the MCP server action consumes no AI credits and counts as a flow · Mode 4 supports Streamable HTTP only, tools only, text responses, a 30-second tool ceiling, 100 concurrent tool calls (1,000 dedicated) · Tool hints default Read only off / Destructive on / Idempotent off / Open world on · the AI Agent action is Business/Enterprise only and unavailable in personal teams, defaults to the fast model without tools, has an Output schema field and Status-tab token alerts · exactly three features consume AI credits and one credit is $0.01 · Agent Skills attach to AI Agent actions (2026-08-11) with CRUD API endpoints (2026-09-01) · audit logs retain two years by default with S3 export every 15 minutes.
