# Build prompts — `[KIT] 00 · Launch Storyworks` (P-K1 to P-K14)

_Spec: REPO-DESIGN.md §7.9 (the prompt list), §15.6 (the maintainer release that uses them), §6.2 (who holds Mode 2), §6.1 (`phase-gate.sh`). The shape of every prompt is the scaffold's (`.claude/skills/tines-build-story/references/prompt-pack.md`): **story name + action type + action name + field names + "Then validate."**_

**`story.json` is never hand-written.** The kit story is built through **Mode 2** (the Tines Stories MCP server), by the `tines-builder` crew member, **one section at a time, each prompt ending with Validate**, in a maintainer **dev team**; then it is exported and committed. That build is the §15.6 maintainer release. It is **not** gated through the `kit-launch` row of `kit/tracker/backlog.yaml`, which cannot pass G1 as the lifecycle checks it: G1 and G2 are reviewed by hand and the session runs with `STORYLINE_ENFORCE=0` (REPO-DESIGN.md §15.6 step 1). The prompts below point the builder at the section and Page files, which hold every action's type, options, formulas and branches — the builder reads them from the repository and never improvises a name.
